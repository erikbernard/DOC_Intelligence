## Documento sobre inicion do projeto e decisões arquiteturais iniciais

Ao ler problematica do projeto, compreendo que seria uma extração de dados por OCR (Reconhecimento Óptico de Caracteres) é uma tecnologia que converte imagens de textos. ja tinha feito projeto pessoal extrair de dados de um cupom fiscal mas estrutura é bem diferente e algoritmo de OCR quando se tratar de documentos desse tipo tem um grau de dificuldade bem maior pois os dado não são acessiveis e tem padrões mais complexos e variados.  Nesse sentido fiz uma busca usadno gemini com deep research para entender as ferramentas disponiveis(sdks, porjeto open source e cobinacao com llm) e qual seria a melhor abordagem para o projeto.
derivada da minha pesquisa decidi por uma abordagem utilizando apenas  EasyOCR e algoritmos matemáticos baseados exclusivamente em filtragem no espectro do OpenCV e normalização espacial pela facilidade de implementar, pelos custos zero e pela capacidade de processamento, poderia ter utilizado VLM Multimodal via Infraestrutura GPU com modelo Qwen2.5-VL mas so roda local e exige GPU.
- O entendimento é que o projeto tem porcessar e extrair dados e que pelo volume de requisições,  decidi adotar um fila para processamento e notifica quando extraçao for concluido, a fila e o OCR seram base do projoto. como quero testar com outros OCR adote dois padroes de projeto que serao essenciais strategy e adapter para torna OCR plugin-play   

Definição das tecnologias a serem utilizadas, adotei python pois se integra melhor de processmanto e extracao de dados,  o framework para desenvolvimento do backend escolhi FastAPI para trabalha com processo assincrono, para filas e notifcição ser utilizado celery e redis, para banco de dados relacional postgres, Frontend vou adotar framework Angular, pois e uma tecnologia que já  domino, por questao praticidade  usarei tailwind e daisyui para contrucao mais rapida.

por questao de simplicidade utlizei minio que simula bucket S3 para salva os dados dos documento e ser combativei com o buckets da AWS. isso por que não deve salva imagem em base64 em banco de dados relacional.

a priori pensei no fluxo da aplicacao onde cliente recebe um link de upload  do documento (PDF ou Imagem) acesso e enviar os documentos, e outro api processar o documento e extrair os dados, e notificar se ocorreu com sucess ou necessita ajsute manual, nesse adiciona a entidade que dona dos documento e dos dados defini como persona. aparte desse ponto posso deriva requisitos e casos de usos.
